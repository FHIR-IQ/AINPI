# Humana provider directory API: terms read on 2026-11-23

Read before the 2026-11-23 Humana sample (`analysis/payer_sample.py humana`), as plan 2026-11-03 Task 5 requires.

## What was read

- https://developers.humana.com/provider-directory-api/doc. The page renders only in a browser. In a browser on 2026-11-23 it redirected to the Developer Exchange home page (https://developers.humana.com/), which describes partner and vendor APIs and links no terms of use for the provider directory API.
- https://www.humana.com/legal, the legal index. It links two pages: "Humana Interoperability API" and "Humana Data Exchange" (the developer portal above).
- https://www.humana.com/legal/humana-interoperability-api. This page covers the member-facing APIs CMS requires: Patient Access, Provider Access, Payer-to-Payer and Prior Authorization. It covers member opt-in, privacy, and choosing a third-party app. It says nothing about the public provider directory API, about rate limits, or about automated access.
- https://www.humana.com/legal/terms-of-use returned Humana's error page on 2026-11-23.

## What this means for the sample

On 2026-11-23, no Humana page we found set terms, limits or prohibitions for the public provider directory API. CMS-9115-F (42 CFR 422.120 for Medicare Advantage) requires the provider directory API to be publicly accessible. The sample stayed inside the project's own caps: 2 requests per second, at most 1,500 requests per run, no credentials, and only the public `Practitioner?identifier=` and `PractitionerRole?practitioner=` searches.

Re-read these pages before any later run. If Humana publishes terms, record them here with the date they were read.
